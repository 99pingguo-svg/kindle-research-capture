# 設計

## 構成（企画書5章の5要素）

| 要素 | 実装 |
| --- | --- |
| 公開Web | `publisher.py` が承認済みの版だけから静的HTMLを生成し、検証後に `var/public_site`（ダミー公開先）を原子的に切り替える |
| 非公開管理画面 | `web/`（標準ライブラリのWSGI＋Jinja2）。本人1名のログイン、CSRF、二重送信防止、セキュリティヘッダー |
| データベース | SQLite（`var/editorial.db`）。WAL、外部キー、`BEGIN IMMEDIATE` による排他 |
| 素材保管 | `var/private_assets/`（SHA-256 で名前付け、権限600）。公開時だけメタデータを除去してコピー |
| 公開ジョブ | `jobs.py`。即時・予約・取り下げ・復元・定期更新。リース付きの排他と冪等キー |

依存は Python 3.9+ と Jinja2 だけです。ホスティング先が決まったら、公開先の種類（`publish.target`）を追加します。

## 状態遷移（企画書4章）

```
draft ──確認依頼──▶ review ──承認──▶ approved ──予約──▶ scheduled
  ▲                 │  │                │ ▲                │
  │           差戻し│  │不採用           │ └──予約取消──────┘
  │                 ▼  ▼                ▼
changes ◀──────── (修正指示)  rejected   公開ジョブ ──成功──▶ published
  │ 新しい版を作って確認依頼  │ 作り直し→draft        └─失敗─▶ error（同じ命令を再試行）
```

- 版は保存のたびに新しく作られ、上書きされません（本線 `main` と提案 `proposal`）。
- `review` 中の編集は版を増やすだけ、`approved/scheduled/error` 中の編集は承認と予約を無効にして `review` に戻し、
  `published` 中の編集は `draft` から改訂を始めます（公開中の版は新版の公開か取り下げまで残ります）。
- 取り下げ後は `review` に戻り、再公開には再承認が必要です。復元は「過去に承認された版」を選び、現在の権利で再検査してから公開します。
- 保管（archived）は編集待ちから外すだけで、履歴は消しません。

## 承認と公開の固定

承認レコード: `version_id`、`content_hash`（本文・画像の選択と順序・トリミング・商品カード・根拠・提供関係）、
`context_hash` と `context_json`（サイト名・運営者名・編集責任者・公開URL・収益化モード・トラッキングID・星評価方針・
広告表示文・AI表示文・テンプレート版）、`amazon_snapshot_json`（承認時の画像ID）、確認済みの注意事項。

公開ジョブは、承認が有効・版とハッシュが一致・公開設定が承認時と同じ・承認後に新しい版がない（復元を除く）・
公開前判定にブロックがない、をすべて満たす場合だけ進みます。公開中のページは、承認時の設定で描画され続けます。

## 公開処理

1. 公開中の記事＋今回の記事で、新しいビルドフォルダにサイト全体を生成（記事・トップ・404・sitemap.xml・robots.txt・CSS/JS・画像）。
2. 検証: ページの存在、タイトル、canonical、AI表示・広告表示・開示文、リンクのASINとタグ、`rel=sponsored`、
   画像の実在とEXIF除去、Amazon画像の期限、`media/` 以外に画像がないこと、Service Worker がないこと、私有情報がないこと。
3. 検証に通ったビルドへ公開先を切り替え（シンボリックリンクの置き換え）、読めることを確認してからDBを確定。
   DBの確定に失敗したら切り替えを元に戻します。古いビルドは既定で5件残します。

## 取り込み（企画書付録2）

`survey` は文書化された入口（`399_assignment`、`audit_399_current_copy`、`master_manuscripts/products/<ASIN>/*.json`、
`FINAL_COPY_AUDIT_COUNTS`、`promotion_completion_ledger`、`RELEASE_DELIVERY` が指す品質報告、部分採用の記録）の
有無・形式・不足項目を報告するだけです。`import` は指定した商品について:

- 現況ファイルで ASIN を一意に特定できなければ保留。監査コピーや原資料のURLのASINが食い違えば保留。
- `source_original.json` は出所「Amazon」として保存（公開・AI入力なし）。`manuscript.json` は出所「不明」とし、本人が許可するまでAIに渡さない。
- 原稿の版が現況と違えば保留。監査版が現行原稿と違えば注記（監査合格を流用しない）。
- 参照写真は `reference_inventory.json` の実在パス・サイズ・ハッシュが一致したものだけを「参照用（公開不可）」として登録（コピーしない）。
- 正式台帳の画像はハッシュが一致したものだけを非公開領域にコピーし、権利は「未確認」、品質は「未判定」で登録。上流の判定は参考情報として残す。
- ファイルは相対パス・サイズ・更新時刻・ハッシュで記録し、変わらないものは読み直さない。取り込み元の外を指すパスは読まない。

## Amazon データ

`amazon_items` に ASIN ごとの URL・タイトル・画像ID・星評価・件数・取得時刻・期限（取得から24時間）を保存します。
定期更新（`tick`）は12時間ごとに再取得し、失敗しても前回の値は期限まで、ItemNotFound は即時に非表示にします。
画像IDが変わったら記録し、承認し直すまで画像を出しません。

## Claude との共同管理（MCP）

既存の「商品台帳」アプリと同じく、Claude はアプリの業務ルールを通して読み書きします（DB を直接触らない）。

| Claude ができる | 本人だけ |
| --- | --- |
| 記事・修正指示・コメント・公開前判定・AI可のメモ/原稿/素材情報を読む、下書き・修正案を「提案」として保存、コメント、メーカー公開ページの事実をメモ（出典URL必須・Amazon不可）、変更イベントを読む | ドラフトの採用、文章整形（Antigravity CLI）、確認依頼・承認・差戻し・不採用、公開・予約・取り下げ・復元、素材の権利と品質、ASIN確認、設定、規約確認 |

- 認証は `create-ai-token` で作るトークン（DBにはハッシュのみ）。ブラウザからの不正利用を防ぐため、localhost 以外の Origin は拒否します。
- 提案は本人の本文を変えず、状態も変えません。止まる表現が含まれる提案は `flags` で Claude に返し、レビューと同じ文を含む提案は受け付けません。
- 収集済みレビュー・Amazon 由来の情報・選定メモ・AI不可のメモは、どのツールからも返しません。
